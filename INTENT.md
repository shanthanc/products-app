# Products App — Intent

## Goal
A basic products app: users create products through a UI, the products are saved to a
database, and the UI shows the list of saved products.

## V1 scope
- Create a product.
- View the list of existing products.

## Design and implementation principles

**Thin vertical slice** - Build the smallest working path through every layer
(UI → API → database) before adding depth to any one of them.

**Convention over customization** - Use standard Java, Spring Boot and React patterns
  and project layout, so anyone familiar with them can find their way around.
  No custom abstractions or unusual folder structures.

**Stay in scope** - Scope will change over time, but build only what the current scope
  asks for. Nothing beyond it.

**Simple layering** - UI → API → database, each with one job. The UI never talks to
  the database. Business rules live in the backend; the UI handles input and rendering.

**Versioned schema** - The database schema is created and changed only through
  migrations in the repo, never by hand.

**Configuration outside the code** - Connection details and ports come from
                                     configuration with local defaults. No hard-coded secrets.

**Clear API contract** - JSON over HTTP, with consistent status codes and a consistent
                         error format the UI can rely on.

**Validate at every layer, enforce at the API** - The UI validates for fast feedback, 
                                 the API is the source of truth and rejects bad input with a clear error, and the
                                 database enforces critical constraints. The UI never relies on its own checks alone.

**Testable layers** - Backend logic and API behavior have automated tests that run with
                      one command. The main user flow is checked end to end.

**Visible failures** - Errors return a consistent, user-safe message to the client and
                       are logged on the server with enough context to diagnose.

**Easy to run** - A new developer goes from clone to running app with a few documented
                  commands and no manual database setup.
 
**Minimal dependencies** - Add a library only when it clearly saves more than it costs.

## Stack

**Frontend: React with TypeScript, built with Vite**
The UI is a single page with a list and a form, so I kept the frontend minimal.
Vite provides the dev server and proxies API calls to the backend.

**Node 26**
Current LTS line. Pinned in `.nvmrc`.

**Backend: Spring Boot (latest GA from Initializr) on Java 25**
A good fit for a small REST API on top of Postgres. Java 25 is the latest LTS and is
supported by Spring Boot 4; using the latest GA keeps the support window as long as possible.

**Build: Gradle (Groovy DSL)**
Short, readable build file and fast incremental builds. The Gradle wrapper is committed,
so nothing extra to install.

**Database: PostgreSQL 18**
Latest stable release, with native UUIDv7 support.

**Migrations: Flyway (version managed by Spring Boot)**
Schema changes live in the repo as versioned migrations.

**Local infrastructure: Docker Compose**
Starts Postgres with one command. The image version is pinned in the compose file.

## Data model

One table, `products`.

| Column | Type | Rules |
|---|---|---|
| `id` | UUID (v7), generated by the database | Primary key |
| `name` | text | Required |

I chose UUIDv7 because a primary key type is expensive to change later. v7 ids are
time-ordered, so they index well, and they aren't guessable.

## Acceptance criteria
- The list shows all saved products.
- Creating a product named `P1` adds it to the list.
- A product without a name is rejected.
- Each product gets an auto-generated id.
- Products are still listed after the app restarts.
- A fresh clone runs by following the README.
