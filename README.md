# Products App

Create products and see the list of saved products. A React UI talks to a Spring Boot REST API,
which stores products in PostgreSQL.

| Part | Stack | Folder |
|---|---|---|
| UI | React + TypeScript, Vite | `client/` |
| API | Spring Boot 4 on Java 25, Gradle | `api/` |
| Database | PostgreSQL 18 (Docker Compose), Flyway migrations | `docker-compose.yml`, `api/src/main/resources/db/migration/` |

Run commands from the repository root unless a section says otherwise, each start step in its own
terminal.

## Prerequisites

- **JDK 25.** Gradle picks it up through its toolchain support, even if another JDK is your default.
- **Node 26** (`node -v`). The version is pinned in `.nvmrc`. If you use nvm, `nvm install` picks it up.
- **Docker** with Compose v2+ (Docker Desktop on macOS and Windows). It runs Postgres locally and
  in the integration tests. You don't need a local Postgres install.

## Database setup

```sh
docker compose up -d
```

This starts Postgres 18 (image pinned in `docker-compose.yml`) on `localhost:20028`. You don't
create the table by hand. Flyway runs the migrations in `api/src/main/resources/db/migration/`
when the API starts, and `V1__create_products.sql` creates the table:

| Column | Type | Rules |
|---|---|---|
| `id` | `UUID` | Primary key, generated by Postgres (`uuidv7()`) |
| `name` | `TEXT` | `NOT NULL`, unique, at most 50 characters, stored trimmed and uppercase (enforced by `CHECK` constraints) |

To stop the database, run `docker compose down`. Your data stays in the `db-data` volume.
`docker compose down -v` deletes it.

## Start backend

```sh
cd api && ./gradlew bootRun
```

The API runs on http://localhost:8080 and applies any pending migrations on startup. Start the
database first.

## Start frontend

```sh
cd client && npm ci && npm run dev
```

The UI runs on http://localhost:3000 and proxies `/api` to the API.

## Verify

Open http://localhost:3000, create a product named `P1`, and confirm the success message appears
and `P1` shows in the first row of the "Saved products" table, with its id. Creating `p1` next
should show "Product creation failed: A product named P1 already exists." Restart the API and the
database, reload the page, and `P1` is still listed.

## Notes

- The stack is the preferred one: React, Java Spring Boot and Postgres.
- `id` is a UUID v7 that Postgres generates (`uuidv7()`, native in Postgres 18). The app never
  generates ids.
- A missing, empty or whitespace-only `name` (including no-break spaces) is rejected by the UI and the API (`400`, with a field
  error). The database backs this up: `NOT NULL`, and a `CHECK` that rejects an empty name or one
  with leading or trailing spaces.
- A name may be at most 50 characters, counted as typed. Longer names are rejected by the UI, the
  API (`400`) and the database.
- Names are stored trimmed and uppercase, with spaces between words kept: `" Some Product Name "` is
  saved as `SOME PRODUCT NAME`. So `P1`, `p1` and ` P1 ` are the same name, and creating one that
  already exists returns `409 Conflict`. The database enforces this too (`CHECK` and `UNIQUE`).


## Configuration

Every value has a local default, so nothing needs setting to run locally.

| Setting | Default | Override with |
|---|---|---|
| Postgres database / user / password | `productdatabase` / `admin` / `pass` (local only) | `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` |
| Postgres port on the host | `20028` (bound to `127.0.0.1`) | `POSTGRES_PORT` |
| API datasource | `jdbc:postgresql://localhost:20028/productdatabase` | `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` |
| API port | `8080` | `SERVER_PORT` |
| UI dev port | `3000` | fixed in `client/vite.config.ts` |

Compose also reads these from a `.env` file in the repository root. That file is gitignored.

If port 20028 is already taken, move both the database and the API to another port:

```sh
POSTGRES_PORT=20029 docker compose up -d
cd api && SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:20029/productdatabase ./gradlew bootRun
```

## API

| Endpoint | Description |
|---|---|
| `POST /api/v1/products` | Create a product from `{"name": "..."}` |
| `GET /api/v1/products` | List all products, newest first |

Errors use `application/problem+json` (RFC 9457). The full contract is in [docs/PLAN.md](docs/PLAN.md).
